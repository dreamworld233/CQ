# 面试讲稿 + 架构图（2.5D 回合制战斗垂直切片）

> 用途：录屏口播 + 面试讲解。规则与数值口径以 `战斗设计.md` 为准。

## 一句话可讲性

速度混排决定出手秩序，敌人意图制造压力，卡牌在回合开始改秩序、做反制。

## 30 秒口播

这是一个 2.5D 异步回合制战斗垂直切片。核心是三样东西套成一个循环：

- **速度混排**决定谁先动，同速我方先，卡牌可临时提速降速，只改本回合顺序。
- **敌人意图**在回合开始就亮出来——普攻、连击、蓄力、强化、全体，玩家据此决策。
- **卡牌反制**：打断让怪本回合不出手、能拆可打断的蓄力；虚弱、护盾、攻增在落地伤害管线里按固定顺序结算。

角色是普攻回能、技能耗能、终结技耗满大招条的经典三循环。全部数值走 JSON 配置，代码零硬编码。

## 架构三件套

### 1. 数据驱动

- 数值全部落 JSON：`StreamingAssets/Data/{Characters,Enemies,Cards,Statuses,Levels}`。
- 加载走 `JsonUtility`（内置），`ConfigValidator` 逐条校验、缺字段即报错。
- 战斗代码（`Core`）零硬编码数值；伤害、速度、能量、状态数值都可改配置热调。

### 2. 确定性状态机

- `BattleEngine`（Core）显式步进：`StartBattle → 输入(打牌/选招) → EndRound(速度混排→逐个结算→死亡→胜负→回合末衰减) → 下回合`。
- `Rng` 可注入 seed，同 seed 全链路结果一致；禁止读 `Time` / `frameCount`。
- Core 零 `UnityEngine` 依赖，可被 NUnit 直接测试、可 headless 重放。

### 3. 测试

- EditMode NUnit 全量；覆盖速度 tie-break、去尾乘法、能量/大招条、意图循环、目标权重、状态时序、打断边界、确定性复验。
- 表现层（Runtime）只读引擎状态、只发指令，不承载规则。

## 接待细节（面试可主动讲）

- 异步回合：小回合 = 我方 3 + 敌方 ≤3 各行动一次，出手顺序双方速度混排。
- 同速 tie-break 我方先；同方同速稳定序（注册序）。
- 伤害管线固定顺序：`基础伤害 × 攻增(源) → 去尾 → × 虚弱(源) → 去尾 → 护盾(目标) → 扣 HP`。
- 打断边界：只对本回合意图已亮生效；打断后本回合不出手、下回合重新亮同意图；可打断蓄力被取消。
- 前后排：只做框架（`row` + `aggroWeight`），单体攻击按受击权重选目标，前排更易受击。

## 录屏分镜（2–3 分钟）

1. **开场（10s）**：一句话可讲性 + 关卡选 1（3 杂兵），点「结束回合」看左侧行动条敌我混排。
2. **速度混排（20s）**：打降速/提速卡，看本回合行动条顺序变化，强调「只改本回合」。
3. **意图压向（30s）**：进第 2 关领主，演示蓄力图标；讲「意图回合开始亮」。
4. **卡牌反制（40s）**：存牌跨回合，蓄力亮时一回合多出打断，领主本回合不出手、蓄力被拆。
5. **收尾（20s）**：三角色能量/大招循环（普攻→技能→终结技），打穿，点架构图收口。

## 数据驱动抽查点（面试可现场改）

- 改 `grunt.json` 的 `baseSpeed`，重开即见行动条顺序变化。
- 改 `lord.json` 的 `charge.nextDamage`，蓄力伤害随之变化。
- 全链路数值无一处写死在 C# 里。
