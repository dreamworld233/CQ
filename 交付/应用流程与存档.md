# 主菜单、应用流程与本地存档

## 本轮范围

启动菜单 → 新建/加载 → 现有战前布阵与自动战斗 → 保存并返回菜单 → 退出后重新加载。

不包含世界观开场、探索地图、任务、NPC、云存档或战斗中途续存；不改变技能与伤害规则。

## 场景与入口

- `Bootstrap`：常驻 `GameApplication`、全局 `EventSystem`、设置、确认弹窗和转场遮罩。
- `MainMenu`：标题菜单、三槽新建/加载、设置入口；离开时卸载。
- `Battle`：已有战斗控制器、战场、摄像机、声音与战斗UI；返回菜单时卸载。
- 构建首场景为 `Bootstrap`。直接从无战斗控制器的旧 `SampleScene` Play，也进入正式菜单。
- 显式放置 `BattleController` 的测试场景仍可直接进入战斗，不创建应用会话、不写玩家存档。编辑器 `CQ/创建战斗测试场景` 可建立此入口。
- 转场在常驻层中遮罩，异步加载内容场景；战斗需报告业务初始化完成才揭开，不以固定延时冒充就绪。

当前UI沿用工程的代码构建方式，按 `MainMenuView`、`ApplicationOverlay`、`AppUi` 分责，未将全部既有UI迁为预制体；未来可替换表现，不改变存档和应用流程契约。

## 存档位置与结构

正式目录：`Application.persistentDataPath/Saves`。

- `slot-1.json` / `slot-2.json` / `slot-3.json`：三份独立游戏存档。
- 同名 `.bak`：上一份有效写入的备份。
- `settings.json`：全局音量、音效音量与静音，不随槽位切换。
- 编辑器/开发构建可通过 `-cqSaveRoot <绝对目录>` 指定隔离验证目录，正式发布构建不开放此参数。

游戏存档v1包含：签名、格式版本、名称、创建/保存UTC时间、随机种子、恢复关卡ID、已完成关卡ID列表、伙伴上阵/下阵与记忆站位。关卡可用伙伴仍由配置决定，不将头像或Unity对象写入JSON。

不保存HP、能量、状态、动作队列、动画进度或对象引用。加载后是新一场战前布阵；生命/能量/状态按现有规则重新初始化。

## 保存时点

- 新建档后先真实写入，再进入战斗。
- 布阵初始化、伙伴上下阵、拖拽落位、开战前。
- 战斗结算：记录通关；若有下一关，恢复目标推进到下一关，保留当前阵容，新伙伴不会自动上阵。
- 战前或战中“保存并返回主菜单”：保存稳定阵容与进度，不保存战斗中途。
- 应用暂停/正常退出时尽力保存；强杀、断电不能依赖退出回调，主要依靠前述检查点。
- 保存失败不能声称成功：开战前保存失败阻止开战，返回前失败提示重试，原已落盘进度保持可用。

## 文件安全与异常行为

- JSON序列化后写同目录唯一临时文件，Flush后原子替换主档；更新时保留上次主档为备份。
- 新建覆盖、删除均经过确认；显式新建覆盖清除旧旅程备份，避免之后恢复出另一份旧游戏。
- 主档损坏/缺失且有有效备份时，加载前提示用户确认，成功保存后修复主档并保留有效备份。
- 更高版本存档不回退为旧备份，不静默改写；不兼容的配置/伙伴也不盲目导入。
- 读取失败、文件过大、非法站位/重复槽位等显示错误；不将损坏存档当空槽自动覆盖。
- 删除先处理备份，再处理主档，防止主档删除后又被备份“复活”。

原子替换减少半写文件风险，不承诺跨平台/断电下绝对不丢数据；目标平台文件系统行为仍需实际构建验证。

## 设置

主音量通过 `AudioListener.volume` 生效，音效音量作用于 `BattleAudio`；战斗内静音按钮同步全局设置。暂无音乐资源，因此不提供不会生效的音乐滑杆。

设置页“保存设置”才持久化并生效，“取消”不改变全局设置。设置损坏时提示并暂用默认值，加载菜单本身不覆盖原文件。

## 如何试玩

1. Unity中使用菜单 **CQ → 运行正式流程**，或打开`Assets/Scenes/Bootstrap.unity`后Play。
2. 新建游戏，填写名称并选择空槽；已有槽覆盖前会再次确认。
3. 调整阵容/拖拽站位后开战，胜利结算后“返回主菜单”并确认保存。
4. 停止Play后重新Play，选择继续游戏或加载该槽；检查关卡与阵容是否保持。
5. 设置页修改音量并保存，重新启动后仍应保留。取消设置、取消删除或取消覆盖均不应改动原数据。

正式目录由Unity的`Application.persistentDataPath`确定，编辑器和不同平台构建可能使用不同位置；开发时不会自动把验证目录的验收档复制给玩家。
